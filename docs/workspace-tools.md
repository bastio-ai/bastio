# Assistant MCP tools and OAuth

Admins add shared tools under **Workspace → Integrations**. Choose a public HTTPS Streamable HTTP MCP endpoint, an authentication method, an optional tool allowlist, and a sharing audience. Personal connections remain governed by the workspace's personal-integration policy. Local stdio and private-network endpoints are not supported by the hosted workspace.

Under **Workspace → Assistants → Edit**, select shared integrations to attach to that assistant. Employees must have access to both the assistant and each integration. Attaching a connection never expands its sharing audience.

In employee chat, open **Assistant tools**, choose any additional permitted integrations, and explicitly enable suggestions. The model receives security-inspected tool descriptions and schemas. OpenAI, Anthropic, Gemini, OpenRouter, xAI, DeepSeek and Groq adapters support function proposals; the selected model must itself support functions. OpenAI tool turns use Responses with provider storage disabled; ordinary chat is unchanged. Ollama and Bedrock tool planning is not yet supported and returns a clear error.

A proposal shows the destination, tool name, protected JSON arguments and security categories. **Run tool & continue** authorizes exactly one invocation. **Decline** does nothing at the remote service. Every tool requires approval, including tools described by the server as read-only. Bastio does not trust server annotations as authorization.

Approvals expire after ten minutes, belong to one employee and conversation, and are atomically claimed once. Editing/deleting the originating message, moving the conversation forward, or changing assistant/integration configuration invalidates old proposals. Access, allowlists, schemas, workspace model policy, member limits and current security protections are checked again. Pending model context is also bound to its security profile and retrieved knowledge versions/access; a policy change, edited source or revoked document invalidates it, including opaque provider reasoning state. A bounded continuation spending reservation is made before the side effect. Remote actions are never automatically retried. If a service times out, the action may already have completed; inspect that service before making a new request.

Arguments are inspected for unsafe commands, validated against the tool's JSON schema, and processed under the workspace security profile before review. External schema references cannot fetch network resources. The exact protected arguments are inspected again before sending. If current protection changes their values, a new request/review is required. Results are inspected as untrusted retrieval content; binary/image content is excluded. Text results over 32 KB are withheld with a request to narrow the query. The assistant then continues with the protected result and may propose another call, which needs another approval. A sequence is bounded to four approvals.

Tool turns bypass response caching. Audit records contain operational identifiers, tool names, actions and category names, never argument/result excerpts. Approval rows retain only operational state. The bounded model context is sealed into an encrypted tenant-bound continuation token without integration/provider credentials. Saved chats may persist the protected card/token under their normal content policy. Temporary chats retain it in browser memory only; durable message content and metadata stay empty. Expired OAuth flow records are removed by maintenance; approval state is retained for up to thirty days after expiration.

## OAuth accounts

Choose **OAuth — connect an account**, save the integration, then choose **Connect account**. Bastio displays the discovered authorization server, MCP resource, requested scopes and callback URL. After **Prepare secure connection**, continue to the service in a new tab and sign in/approve there. Return and choose **Close & refresh**. Shared account authorization is restricted to workspace administrators; employees can connect their own personal integrations when permitted.

Bastio supports pre-registered client IDs (with an optional secret), hosted Client ID Metadata Documents when supported by the authorization server, and dynamic client registration for compatible existing services. A service without automatic registration needs its pre-registered client ID; its client registration must permit the callback URL shown in the dialog. Replacing a confidential client requires entering its secret again.

Authorization uses PKCE S256 and an encrypted, ten-minute, one-use state bound to the tenant, user and connection configuration. The authorization server issuer is validated during discovery and checked exactly against the callback's `iss`; missing `iss` is rejected when the server advertises support. The MCP resource indicator is included at authorization, exchange and refresh. Access/refresh tokens and client secrets are encrypted per tenant and connection and never returned to the browser or forwarded to a model. Refresh is serialized so concurrent tool requests do not race a rotating refresh token. Metadata/registration/token requests use public HTTPS, pinned DNS, no redirects and no environment proxy. A failed refresh requires reconnection.

Disconnecting removes stored access and refresh tokens from Bastio. To revoke the grant at the service as well, use that service's account permissions. Changing the endpoint or authentication method also disconnects the stored account.

Bastio Cloud configures trusted origins from `BASTIO_PUBLIC_URL` (default `https://cloud.bastio.com`) and `BASTIO_WORKSPACE_URL` (default `https://workspace.bastio.com`). OSS operators explicitly set `BASTIO_MCP_OAUTH_BASE_URL` and optionally `BASTIO_MCP_OAUTH_EMPLOYEE_URL` to public HTTPS origins. The callback is `/v1/workspace/mcp/oauth/callback`; the public metadata document is `/v1/mcp/oauth/client-metadata`. Origins never derive from the request Host. OAuth callbacks require the same signed-in user and active workspace. A custom domain without a session shared with the configured callback origin needs a sign-in there before connecting.

Provider inference usage continues to be billed by the customer's own provider. Bastio-managed credits are not part of this feature.
