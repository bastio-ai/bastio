OpenAI is the most common provider behind a Bastio proxy. Once
you've created the proxy, every existing OpenAI SDK call works
unchanged — only the `baseURL` moves from
`api.openai.com` to your Bastio gateway.

## Prerequisites

- An OpenAI account with API access and a funded billing balance
- A running Bastio gateway ([Getting started](/docs/getting-started))

## Get an API key

1. Sign in at [platform.openai.com](https://platform.openai.com/api-keys).
2. Create a new secret key. Pick a project so usage is scoped.
3. Copy the `sk-…` value — you can't retrieve it again.

Project-scoped keys work with their project permissions. When your client
needs `OpenAI-Organization` or `OpenAI-Project`, Bastio forwards those headers.

## Create the proxy

Store the OpenAI credential in **LLM Gateways** first, then create the routing proxy:

```bash
curl -X POST http://localhost:4000/v1/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "prod-openai",
    "slug": "prod-openai",
    "target_provider": "openai",
    "target_model": "gpt-4o"
  }'
```

Create the Bastio gateway key separately under **Developer API → API Keys**. This is the key your application sends to Bastio. Bastio holds your OpenAI credential on its side and never returns it.

## Send a request

```bash
curl http://localhost:4000/v1/chat/completions \
  -H "Authorization: Bearer $BASTIO_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

### Python

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:4000/v1/openai",
    api_key=os.environ["BASTIO_GATEWAY_KEY"],
)

resp = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)
print(resp.choices[0].message.content)
```

### Node.js

```ts
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:4000/v1/openai",
  apiKey: process.env.BASTIO_GATEWAY_KEY,
});

const resp = await client.chat.completions.create({
  model: "gpt-4o",
  messages: [{ role: "user", content: "Hello" }],
});
```

## Supported features

The `/v1/openai` SDK base forwards OpenAI's native API paths, including Chat
Completions, Responses, embeddings, model discovery and multipart uploads.
JSON fields such as reasoning, tools, structured outputs and content parts pass
through without a fixed Bastio parameter allowlist. Native errors, request IDs,
rate-limit headers and SSE event types are preserved. OpenAI project,
organization and beta headers are forwarded when provided.

Text inside user content parts, tool results and Responses input is scanned and
masked or tokenized according to policy. Binary attachments are not decoded or
inspected. Response PII scanning and token restoration buffer SSE events before
release; see [Gateway streaming](/docs/gateway#streaming).

### Responses API

```python
response = client.responses.create(
    model=os.environ["OPENAI_MODEL"],
    input="Hello",
)
print(response.output_text)
```

Choose a model supported by the requested API. Bastio preserves the provider's
validation errors and does not silently substitute a model or API contract.

## Models

Pick any current OpenAI model — Bastio infers the family from the
`model` field on the request, no extra config. For an up-to-date
list and pricing, see
[OpenAI's model docs](https://platform.openai.com/docs/models).

Use `/v1/openai/models` to discover the models available to your credential.
Model availability and supported parameters are determined by OpenAI.

## Gotchas

- **Project-scoped keys.** `sk-proj-…` keys are scoped to one
  project; if the project hits its usage cap, OpenAI returns
  `insufficient_quota` (not a Bastio error). Check the project's
  billing page.
- **`o1` models don't accept `temperature`.** Standard OpenAI
  behavior — Bastio passes the request through unchanged, so
  the 400 you see is from OpenAI, not us.
- **Streaming + tool calls.** Some older clients buffer full
  responses before parsing — make sure your client supports
  the streaming `tool_calls` delta format.

## Where the request shows up in traces

Every request through the OpenAI proxy lands in the dashboard's
Traces tab with `provider: openai`, the model you sent, and the
threat scan result. See [Observability](/docs/observability) for
the trace anatomy.

### Provider-stored state and PII tokens

Reversible PII mappings live only for the current request. Native requests use
unique placeholders, so a token retained in `previous_response_id`, a stored
response, a conversation, or a background job cannot resolve to another
request's PII. Retrieving provider-stored output later leaves older placeholders
intact. To restore all values, send the original conversation input with each
request; use masking when you prefer permanent redaction in provider-side state.
Bastio never persists the reversible mapping.
