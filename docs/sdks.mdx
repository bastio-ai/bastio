The first-party TypeScript packages put `POST /v1/detect` into custom LLM pipelines without coupling your application to Bastio server internals.

> The SDKs currently target a self-hosted Bastio direct API. Bastio Cloud service keys authenticate the managed LLM Gateway, not the standalone detect route. See [authentication and environments](/docs/developer-apis/authentication).

<Callout type="warn" title="Preview packages">
  The TypeScript packages currently live in the Bastio repository and are not presented as generally available npm releases. Use the REST API for stable external integrations; use the packages through the monorepo workspace when evaluating the adapters.
</Callout>

## Package matrix

| Package | Integration | Block behavior | Output behavior |
|---|---|---|---|
| `@bastio/core` | Any server-side TypeScript application | Returns `should_block`; caller decides | Caller uses `sanitized_content` |
| `@bastio/mastra` | Mastra input/output processors | Throws `BastioBlockedError` | Rewrites text-bearing messages |
| `@bastio/vercel-ai` | Vercel AI SDK language-model middleware | Throws `BastioBlockedError` | Scans non-streaming generated text |

## Low-level TypeScript client

From a Bastio source checkout, build the TypeScript workspace before importing `@bastio/core` from another workspace package:

```bash
pnpm --dir sdk/js install
pnpm --dir sdk/js build
```

```ts
import { BastioClient, BastioBlockedError } from "@bastio/core";

const bastio = new BastioClient({
  baseURL: process.env.BASTIO_API_URL!,
  timeoutMs: 3_000,
});

const result = await bastio.detect({
  profile: "default",
  direction: "input",
  messages: [{ role: "user", content: userPrompt }],
});

if (result.should_block) {
  throw new BastioBlockedError(result);
}

const safePrompt = result.messages[0]?.sanitized_content ?? userPrompt;
return callYourModel(safePrompt);
```

The core client throws `BastioError` for timeouts, transport failures, non-success HTTP responses, or invalid JSON. It does not throw for a detection block because `/v1/detect` reports policy outcomes in a successful `200` response.

## Vercel AI SDK

The adapter is available as the `@bastio/vercel-ai` package inside `sdk/js`.

```ts
import { wrapLanguageModel } from "ai";
import { openai } from "@ai-sdk/openai";
import { bastioMiddleware } from "@bastio/vercel-ai";

const model = wrapLanguageModel({
  model: openai("gpt-4o"),
  middleware: bastioMiddleware({
    baseURL: process.env.BASTIO_API_URL!,
    profile: "default",
    timeoutMs: 3_000,
    onDecision(stage, result) {
      securityMetrics.record(stage, result.action);
    },
  }),
});
```

Input content is scanned before the provider call. Non-streaming generated text is scanned when `scanOutput` is enabled, which is the default.

### Streaming limitation

The current Vercel AI SDK adapter passes `wrapStream` through without output scanning. Detectors reason over complete text and partial-token windows can create false positives. If streamed output requires enforcement, assemble and scan it in a controlled completion callback or use non-streaming generation.

## Mastra

The adapter is available as the `@bastio/mastra` package inside `sdk/js`.

```ts
import { Agent } from "@mastra/core";
import {
  BastioInputProcessor,
  BastioOutputProcessor,
} from "@bastio/mastra";

const bastioOptions = {
  baseURL: process.env.BASTIO_API_URL!,
  profile: "default",
  timeoutMs: 3_000,
};

export const supportAgent = new Agent({
  id: "support",
  inputProcessors: [new BastioInputProcessor(bastioOptions)],
  outputProcessors: [new BastioOutputProcessor(bastioOptions)],
});
```

The processors extract text content, preserve non-text parts, rewrite sanitized text, and throw `BastioBlockedError` when the profile chooses `block`.

## Python and Go

The Python client currently supports the OpenAI-compatible gateway plus management helpers; it does not expose a typed `detect()` method. Call the [REST contract](/docs/developer-apis/detect) with your preferred HTTP client for direct detection.

A first-party Go direct-detect client is not currently shipped. Go applications can use `net/http` against the same REST contract.

## Client options

| Option | Type | Default | Description |
|---|---|---|---|
| `baseURL` | string | required | Bastio server URL without `/v1/detect` |
| `apiKey` | string | omitted | Optional bearer token for deployments whose ingress accepts it |
| `timeoutMs` | number | `10000` | Per-call timeout in milliseconds |
| `fetch` | `typeof fetch` | global fetch | Custom runtime transport or test stub |
| `headers` | object | `{}` | Extra headers applied to every request |

## Testing

Inject `fetch` to test allow, block, sanitize, timeout, and malformed-response behavior without a network dependency:

```ts
const client = new BastioClient({
  baseURL: "https://bastio.test",
  fetch: async () =>
    new Response(JSON.stringify(mockBlockedDecision), {
      status: 200,
      headers: { "Content-Type": "application/json" },
    }),
});
```
